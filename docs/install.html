pnk почта · инструкция запуска

Как поставить и запустить проект полностью

Два сервиса: pnk-id (аккаунты / вход) и pnk-mail (сама почта). Ниже — локальный запуск и production на VPS, чтобы письма ходили как у обычной почты (в том числе на @yandex.ru).

Содержание 1. Архитектура 2. Локальный запуск (Windows / Mac / Linux) 3. VPS: установка с нуля 4. Переменные окружения 5. DNS + доставка на Yandex/Gmail 6. OAuth между ID и почтой 7. Проверка «как обычная почта» 8. Частые проблемы

1. Архитектура

pnk-id

Порт 3100

Регистрация, логин, кабинет, OAuth. База SQLite (Prisma).

pnk-mail

Порт 3000

UI почты, ящики, отправка. База SQLite (Prisma).

КудаКто доставляет
user@pnkmail.ru → другой @pnkmail.ruСразу в БД (Inbox / Sent)
На @yandex.ru / GmailResend или Amazon SES + DNS (SPF/DKIM/DMARC)
Входящие с интернета на ваш доменФаза 2: MX + Inbound (пока не обязательно)
Важно Если MAIL_TRANSPORT=console, письма наружу не уходят — только пишутся в лог сервера. Внутри @pnkmail.ru при этом всё работает.

2. Локальный запуск

  1. Нужно

    Node.js 20+, Git, два каталога: pnk-id и pnk-mail.

  2. pnk-id 
    cd pnk-id
npm install
# создайте .env (см. раздел 4)
npx prisma db push
npx prisma db seed
npm run dev
# → http://localhost:3100
  3. pnk-mail 
    cd pnk-mail
npm install
# создайте .env.local из .env.local.example
npx prisma db push
npm run dev
# → http://localhost:3000
  4. Проверка локально

    Откройте почту → «Создать ящик» / Войти через ID → напишите письмо на второй @pnkmail.ru аккаунт.

3. VPS: установка с нуля (Ubuntu 22.04+)

  1. Сервер

    2+ GB RAM, открыты порты 22, 80, 443. Домен указывает A-записями на IP VPS.

  2. Node.js + Nginx + Certbot 
    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt update
sudo apt install -y nodejs nginx certbot python3-certbot-nginx git
node -v   # v20+
npm i -g pm2
  3. Клонирование 
    sudo mkdir -p /var/www
cd /var/www
# подставьте ваши git-репозитории
sudo git clone <url-pnk-id> pnk-id
sudo git clone <url-pnk-mail> pnk-mail
sudo chown -R $USER:$USER /var/www/pnk-id /var/www/pnk-mail
  4. Сборка ID 
    cd /var/www/pnk-id
npm ci
# заполните .env (раздел 4) — APP_URL=https://id.pnkmail.ru
npx prisma db push
npx prisma db seed
npm run build
pm2 start npm --name pnk-id -- start -- -p 3100
  5. Сборка Mail 
    cd /var/www/pnk-mail
npm ci
# заполните .env.local (раздел 4)
npx prisma db push
npm run build
pm2 start npm --name pnk-mail -- start -- -p 3000
pm2 save
pm2 startup
  6. Nginx

    Файл /etc/nginx/sites-available/pnk:

    server {
  server_name id.pnkmail.ru;
  location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}

server {
  server_name pnkmail.ru www.pnkmail.ru;
  client_max_body_size 20m;
  location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
    sudo ln -sf /etc/nginx/sites-available/pnk /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d id.pnkmail.ru -d pnkmail.ru -d www.pnkmail.ru

4. Переменные окружения

pnk-id → файл .env

DATABASE_URL="file:./dev.db"
APP_URL="https://id.pnkmail.ru"
COOKIE_NAME="pnk_id_session"
SESSION_SECRET="вставьте_openssl_rand_hex_32"
JWT_SECRET="другой_openssl_rand_hex_32"
NEXT_PUBLIC_MAIL_URL="https://pnkmail.ru"
NODE_ENV="production"

Секреты: openssl rand -hex 32

pnk-mail → файл .env.local

DATABASE_URL="file:./dev.db"
NEXT_PUBLIC_PNK_ID_URL="https://id.pnkmail.ru"
NEXT_PUBLIC_MAIL_URL="https://pnkmail.ru"
PNK_ID_CLIENT_SECRET="тот_же_секрет_что_в_seed_OAuth_клиента"
MAIL_FROM_DOMAIN="pnkmail.ru"
MAIL_TRANSPORT="resend"
RESEND_API_KEY="re_xxxxxxxx"
NODE_ENV="production"

Вариант Amazon SES

MAIL_TRANSPORT="ses"
SES_SMTP_HOST="email-smtp.eu-central-1.amazonaws.com"
SES_SMTP_PORT="587"
SES_SMTP_USER="..."
SES_SMTP_PASS="..."
PNK_ID_CLIENT_SECRET в production обязателен. В БД ID секрет клиента хранится как SHA-256 (см. prisma/seed.ts). После смены секрета обновите seed / запись OAuthClient.

5. DNS + доставка (иначе Яндекс не примет)

ТипИмяЗначение
A@IP вашего VPS
AidIP вашего VPS
TXT@v=spf1 include:_spf.resend.com ~all
или include:amazonses.com
CNAME/TXTиз панели Resend/SESDKIM (обязательно)
TXT_dmarcv=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc@pnkmail.ru
  1. Зарегистрируйте домен pnkmail.ru в Resend или SES.
  2. Добавьте DNS-записи → дождитесь статуса Verified.
  3. Пропишите ключи в .env.local, перезапустите: pm2 restart pnk-mail.
  4. Отправьте тест на свой @yandex.ru.

Без SPF/DKIM/DMARC Яндекс кладёт в спам или отклоняет. Не шлите «голым» Postfix с IP VPS без прогрева — для старта SES/Resend надёжнее.

6. OAuth: связать ID и почту

В seed ID клиент pnk-mail должен иметь redirect:

https://pnkmail.ru/api/auth/callback/pnk-id

Локально:

http://localhost:3000/api/auth/callback/pnk-id

URL входа с почты: https://id.pnkmail.ru/login?service=mail (это уже делает код через NEXT_PUBLIC_PNK_ID_URL).

7. Чеклист «работает как обычная почта»

✓ Регистрация на ID, вход в /mail

✓ Письмо между двумя ящиками @pnkmail.ru видно во «Входящих»

✓ Ответ/новое письмо сохраняется в «Отправленные»

✓ Письмо на @yandex.ru / Gmail приходит (не только в console-лог)

✓ HTTPS на обоих доменах, куки Secure в production

~ Входящие с чужих доменов на ваш MX — отдельная фаза (пока нет)

8. Частые проблемы

СимптомЧто проверить
Письмо на Yandex не приходит MAIL_TRANSPORT не console; ключ Resend/SES; DNS Verified; смотреть спам
После логина ошибка token / redirect redirect_uri в OAuth клиенте = ваш HTTPS callback; совпадает CLIENT_SECRET
EADDRINUSE :3100 / :3000 Уже запущен старый процесс — pm2 ls / убить PID
Пустой inbox после входа npx prisma db push в pnk-mail; cookies сессии; смотреть Network → /api/mail/messages
JWT / invalid_token Один и тот же JWT_SECRET у ID; не пересоздавали БД без перелогина
